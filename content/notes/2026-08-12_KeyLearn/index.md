## 前言
作为技术小白且非计科专业学生，配置Git时我是一头雾水地跟着教程走又一头雾水的完成了配置，看着一切正常却忽略了许多底层原理。以至于每当我点开一个开源项目的Code，Clone那一栏的HTPS和SSH两个方式总会让我疑惑（现在看更疑惑的是我直接忽略掉了Github CLI）：**同样可以达到克隆项目的目的，这两种方式有何区别？**
直观的感受上，https的clone速度较慢，但通常一定时间后能下载下来；ssh则似乎有点看网络条件，条件良好则不一会即可clone完成，但大多数不配置代理工具的情形下收获的都是一个Timeout。
除此之外，Git配置过程中在本地配置的私钥与复制到Github个人帐号的公钥又是如何完成 **“上锁”与“解锁”** 的？
这些问题曾困扰我，而当最近学习Linux系统编程时，这些词汇再次频繁出现，我不能再将其视作 **房间里的大象**了。因此我查阅了一些资料并将自己的收获总结为笔记，仅代表个人见解，望各位批评指正。

## HTTPS与SSH
**本质区别**
- HTTPS链接：使用443端口。这是网页浏览的标准端口，所有防火墙默认放行。你需要输入用户名+密码（或Token令牌）来验证身份。
- SSH链接：使用22端口。这是远程登录的标准端口。你需要配置公钥+私钥来进行加密身份验证，无需每次输密码。
- 在国内，由于某些网络策略，GitHub的22端口（SSH）时常遭受干扰，而443端口（HTTPS）因为有TLS加密且是网页流量，反而更稳定。

## SSH的公钥和私钥

### 签名和验签算法的流程
在Git配置时，通常会在Git Bash输入
```bash
ssh-keygen -t ed25519 -C "your_email@example.com"
```
>Ed25519 是一种椭圆曲线数字签名算法（EdDSA），专门做数字签名，是用来做身份校验、防篡改。SSH、git、密钥登录大量在用。椭圆曲线数字签名算法下面会提及，暂且不表。

此时，在~/.ssh下会生成`id_ed25519`和`id_ed25519.pub`文件，前者是私钥，万不可泄露；后者是公钥，需复制给Github中个人Settings里的SSH Keys

---

**重点来了**，当` git clone `时，如果选的 SSH 方式（比如 `git@github.com:用户名/仓库名.git`）， Git 并不会直接发送请求，而是先调用电脑里的 SSH 客户端程序。SSH 客户端向 GitHub 的 22 端口发起连接请求，并告诉 GitHub：“我是 git 用户，我想用公钥认证”。
SSH 连接到服务器的那一瞬间，GitHub 服务端会抛出一个“随机字符串（质询）”给我的 SSH 客户端。SSH 客户端拿到这个随机字符串后，立刻用电脑里藏着的私钥对该字符串进行数字签名，然后把签名结果发回给 GitHub。
GitHub 收到签名后，立刻去它刚才存好的公钥进行验签，GitHub 才确认“对面这台电脑确实持有匹配的私钥，是本尊”。 **整个过程叫“签名-验签”，不传输密码，也不传输公钥本身，只传输签名结果，所以极其安全。**
验签成功后，GitHub 打开一个加密通道（SSH 隧道）。此时本地 Git 程序才通过这条加密隧道发送 `git-upload-pack `请求，告诉 GitHub“我要拿这个仓库的所有对象”。GitHub 把仓库打包成压缩流，通过隧道加密后传回。本地 Git 收到数据后，在本地工作目录里解包、重建目录树，最终把代码文件还原到指定的路径下。

### 签名和验签算法的实现
公钥与私钥的特点在于
- **正向容易（私钥 → 公钥）**
- **反向极难（公钥 → 私钥）**

在数学上，两者称为是一个 **“非对称陷门函数”的配对** ，算法（如Ed25519）会基于一个巨大的随机数种子，通过 **椭圆曲线点乘运算**，同时生成两个数

- 私钥（d）：一个随机大整数。
- 公钥（Q）：由私钥通过“单向陷门函数”计算得出（$Q=d×G$，G是公开基点）。

这个运算的意义仅凭笔者贫乏的描述能力难以表达，可参考此视频
[公钥加密技术ECC椭圆曲线加密算法原理](https://www.bilibili.com/video/BV1BY411M74G/?spm_id_from=333.788.top_right_bar_window_history.content.click&vd_source=87b52e0742bfb06e0d4c873fc9665d77)。

上述运算的 $×$ 也不是简单意义的标量乘法，实际数学逻辑是：
- `Q = d × G `在椭圆曲线中，表示“将点 G 与自己进行 d 次点加运算”。
- 点加规则（特殊运算）：给定两个点 P 和 R，经过“画切线、找交点、取对称点”的几何规则，生成第三个点 S。这种运算不满足普通的数乘分配律，而是**基于椭圆曲线群上的加法**。

听上去有点绕，但表达的意思简而言之，如果将G（公开的）和Q（公开的）视作曲线上两个点，现在你能从G通过d次变换得到Q，但反推回原点甚至反推出“正步骤”难如登天。正如上面视频的“颜色”比喻：**给你两桶颜料，把它们搅匀，得到一桶新颜料，这非常容易；给你这桶混合好的新颜料，让你逆向分析出原本那桶私钥颜料的确切成分和分量，这在物理和数学上都是几乎不可能完成的任务。**

---

事实上，公钥和私钥的设计使用远比混合颜料更复杂（毕竟混合颜料还可视作线性的过程），具体操作可分为 **哈希凝练、签名生成、验签**三步。

- 哈希凝练：将消息 M、随机点 R 和公钥 A 压缩（实际上是一个 $h = SHA-512(R||A||M)$ 的公式）成固定长度整数 h。其中M为验证方（只拿着公钥的一方，例如Github方）抛过来的随机字符串，随机点R的计算第二步会提及，但该过程不涉及私钥，意味着验证方可以独立计算出h。
- 签名生成：由持有私钥的一方，用数学方法把 h 和私钥绑定，生成不可伪造的签名对 `(R, S)`。持有方生成一个一次性随机盲因子整数r（生成遵循一定规律），通过椭圆曲线乘法 $ R = r \cdot G $ ，算出随机点；使用私钥标量 a，计算 $S=(r + h * a)\ mod \ L $（模 L 是曲线群的阶，确保结果落在有限域内）。序列化 (R, S)，长度共 64 字节（R 占 32 字节，S 占 32 字节）。
- 验签验证：验证方此时拥有：公钥`A`，原始消息`M`，收到的签名`（R,S）`。反解h后，验证方在等号左侧放上 $LHS=S \cdot G$ ，右侧放上 $RHS=R+h \cdot A$ 。由于椭圆曲线点乘满足结合律，验证$LHS=RHS$恒成立则验签通过。
